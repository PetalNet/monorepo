# New imagery integration

Branch: envgen/new-imagery, based on #848 (974414f6). Worktree: /home/agent/work/envgen-imagery.

Run `python -m envgen.imagery_config SITE DATA OUTPUT` to produce a configured site. On the PC, DATA is `/opt/envgen/data/imagery-hunt-2026-11-19`. It preserves the NAIP ImageServer for tile and 4032 m context; tile acquisition changes from 0.6 to 0.3 m. Context imagery uses the 2048-pixel colour budget, about 1.97 m per pixel for that surround, independently of its 8 m terrain grid. Never replace the service with the tile-only NAIP crop for a context build.

Ground: `site.mask_imagery` is RGB+NIR MSDIS 2024 leaf-off, native EPSG:6344 at 15 cm. `imagery.read(source, crs, tile)` reprojects to the requested grid and returns spectral data plus validity. The surface stage applies it only outside fully opaque drone alpha, preserving the existing drone masks and detail path. Your native survey masks should still override the result. Use the source at native resolution for finer paths/soil evidence; do not use winter RGB for colour. Roof edges remain evidence for the buildings builder; roof pixels are excluded from ground as before.

Procfill: use `site.mask_imagery` via `imagery.read`, with band four as NIR. The surface manifest records mask source priority and fitted splits. If winter populations overlap, a vegetation threshold is fitted to the leaf-on reference labels, with balanced agreement recorded. With no usable separation, existing masks are retained. Existing colour is NAIP/drone, never the winter raster. Do not project drone masks outside valid alpha.

Buildings: `site.microsoft_buildings` and `site.osm_features` expose separate file sources. `vector_sources.load(source, "microsoft")` returns WGS84 GeoJSON features, retaining `height` and adding positive `height_m` plus `height_evidence` = model estimate. Missing heights stay null. `load(source, "osm")` retains all OSM buildings/sports/tags and polygon holes. You own selection, overlap reconciliation, geometry projection and measured lidar height priority. No footprints are automatically appended to Overture.

Streetscape: `site.osm_features` includes sports features and original tags, available with `vector_sources.load(source, "osm")`. Use these as dated observations; the database timestamp is not an acquisition date.

Every build's source registry includes hashes, dates, licence links, attribution, and MSDIS conflict/internal-only fields. MSDIS publisher CC BY 4.0 conflicts with restrictive delivery XML: all staged data and derived masks stay internal. NAIP is public domain; Microsoft is CDLA Permissive 2.0; OSM is ODbL with attribution and database obligations.

The surface stage also exports `leafoff_masks.tif` at native 15 cm in the source CRS, recorded under `surface.mask_sources.native`. Bands are grass, paved, soil and validity, each uint8 0/255; the first three sum to validity. This is fallback evidence, including inferred roof/canopy classes. Apply building exclusions and override it with valid drone masks. It does not include drone pixels itself. Fitted thresholds live under `surface.mask_sources.evidence.mask_imagery.fit.splits`; classify finer blocks with `surface.apply_splits` or consume the exported raster. Seasonal colour calibration and the context classifier continue to use the NAIP splits.

Validation caveats: winter NDVI populations overlap under the existing unsupervised mixture criterion. Their vegetation threshold is therefore calibrated against NAIP reference labels, with balanced reference agreement recorded, not ground-truth accuracy. Soil/paving remain inherited where their own split is unresolved. The original reference labels are kept separately for native inheritance, including bare native pixels under coarse vegetation cells. The real comparisons show cleaner path and infield boundaries; vehicles can still cause small false vegetation regions. Different seasons/dates contribute to the comparison as well as pixel spacing. The current native masks are useful evidence for the ground builder, not surveyed labels for every material.

Survey reservation uses fourth band == 255, matching the existing survey-detail consumer even if GDAL has not tagged that band as alpha. It also follows the consumer's matching-CRS and at-least-four-band eligibility rules. Partially transparent fringe pixels remain eligible for fallback; generic raster reads can still accept nonzero alpha. Combined tests run the real survey-detail builder for partial-only and mixed opaque/partial coverage, including a coarse-cell boundary.
